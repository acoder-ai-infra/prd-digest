# 方法论与评审维度映射

## 1. 使用原则

本 Skill 借鉴方法论背后的判断原则，不要求 PRD 出现方法论名称。

不得因为 PRD 没写“JTBD”“RICE”或“HEART”就扣分。

## 2. JTBD

抽取原则：

- 用户在特定情境中要完成什么任务；
- 当前使用什么替代方案；
- 用户想取得什么进展；
- 什么推动或阻碍用户改变；
- 功能请求不等于底层任务。

主要影响：

- 需求成立度；
- 方案适配与业务闭环；
- 小型需求的问题与价值、方案闭环。

## 3. RICE

默认使用：

- Reach：覆盖范围；
- Impact：影响强度；
- Confidence：证据可信度。

默认不使用 Effort，因为本 Skill 不评价详细技术可行性和研发工作量。

主要影响：

- 价值与影响；
- 证据等级和评审置信度。

不计算标准 RICE 总分。

## 4. Assumption Mapping

抽取原则：

- 把事实与假设分开；
- 判断假设重要性和证据强度；
- 优先验证高重要性、低证据假设；
- 识别致命假设；
- MVP 应服务于关键假设验证。

它作为横向机制，不再单独占一个评分维度。

## 5. MoSCoW

抽取原则：

- Must：没有它本期核心交付或验证就失败；
- Should：重要但存在临时替代方案；
- Could：有价值但不影响本期核心目标；
- Won't：本期明确不做。

主要影响：

- 范围与复杂度控制；
- 小型需求的范围与复用。

## 6. HEART

抽取原则：

- Happiness：满意度和信任；
- Engagement：参与深度；
- Adoption：首次采用；
- Retention：持续使用；
- Task Success：任务完成质量。

同时使用 Goals-Signals-Metrics：

- Goal：希望达到什么状态；
- Signal：什么行为或反馈说明目标实现；
- Metric：如何量化。

主要影响：

- 体验与信任；
- 验证与可逆性；
- 方案中的任务成功判断。

不要求每个需求使用全部五项。

## 7. 能力复用与产品杠杆

这是基于产品架构、平台治理和产品能力地图抽象出的自定义评审维度，不直接对应单一经典方法论。

它区分：

- 向内复用：利用已有能力，减少重复产品设计和用户心智；
- 向外杠杆：新增能力服务于多个明确相邻场景；
- 新增边界：哪些必须新建；
- 过度平台化：为不确定未来过早通用化。

它不等同于代码复用或技术架构复用。

## 8. 轻量 UX 与产品信任

体验与信任吸收了：

- HEART 的 Happiness 和 Task Success；
- 用户控制权；
- 系统状态透明；
- 错误恢复；
- 自动化可解释性；
- 暗黑模式和善意消耗检查。

它不是完整 UI 或可用性审计。没有视觉材料时，不评价像素级设计。
