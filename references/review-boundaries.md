# 评审能力边界与专项评审触发

## 1. 产品需求评审的重点

本 Skill 重点负责：

- 用户问题和价值；
- 产品方案和业务闭环；
- 产品层体验与信任；
- 范围、复用和复杂度；
- 验证和产品可逆性。

它不试图覆盖产品研发的全部专业工作。

## 2. UI 与 UX 边界

### 2.1 可以评价

即使没有完整设计稿，也可以评价：

- 用户任务流程；
- 主要入口和操作步骤；
- 系统反馈；
- 用户控制权；
- 取消、撤销和退出；
- 自动化透明度；
- 明显打扰和信任风险；
- 主要状态和恢复路径。

### 2.2 需要原型或设计稿才能评价

- 信息层级；
- 视觉注意力；
- 表单布局；
- 控件选择；
- 具体错误文案；
- 页面间一致性；
- 多端适配；
- 微交互。

### 2.3 默认不承担

- 像素级视觉审美；
- 设计系统完整审查；
- 完整 Nielsen 启发式评估；
- WCAG 合规审计；
- 正式可用性测试。

需要时触发独立 UX Review。

## 3. 用户研究边界

本 Skill 可以判断：

- 有没有用户证据；
- 证据是否支持结论；
- 哪些假设需要验证。

不能代替：

- 用户访谈；
- 行为数据；
- 可用性测试；
- 客服和销售事实；
- 真实灰度或实验。

## 4. 商业论证边界

可以评价商业价值链是否清楚，但不代替完整 Business Case，包括：

- 市场规模；
- 定价；
- 获客成本；
- 生命周期价值；
- 毛利和现金流；
- 渠道与销售周期；
- 投资回报。

新产品和大型商业化项目应触发商业论证评审。

## 5. 技术评审边界

可以识别：

- 跨系统依赖；
- 缺失数据能力；
- 产品级不可逆操作；
- 需要灰度、开关和恢复。

默认不判断：

- 服务拆分；
- 数据库设计；
- 接口复用；
- 性能和容量；
- 技术迁移；
- 技术降级和回滚；
- 研发工作量。

这些内容应触发技术方案评审。

## 6. 法务、安全与合规边界

可以识别明显风险，但不能给出专业结论。

出现以下内容应触发专项评审：

- 敏感个人数据；
- 默认授权；
- 金融、医疗、未成年人；
- 自动决策；
- 内容治理；
- 不可撤销操作；
- 跨境数据；
- 欺骗性设计。

## 7. 专项评审触发格式

默认摘要可增加：

```markdown
【专项评审触发】
1. UX Review：需要原型确认复杂多步骤流程和错误恢复
2. 技术方案评审：涉及跨系统核心链路替换
3. 法务与隐私评审：涉及敏感数据授权
```

没有明确触发项时不输出该区块。
